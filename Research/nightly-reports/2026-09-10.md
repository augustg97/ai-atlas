## Findings

### 1. The state-law witness dropped the night's only notable event — and the 300-char cap is not why

`ev-state-law-enacted` fired on the California signing and moved C by 1.23pp. The counter that
feeds the calibration claim did **not** count it: `observed_count` stayed at 8, and the newest
law in the series is still 2026-07-31.

Both components share the matcher by construction — `witness_statelaw.enactment_rule()` reads
`ev-state-law-enacted` out of `axes.py` precisely so "the counter and the forecast can never
drift apart on what counts". That guarantee held: `axes.match_event(rule, ev)` is `True` on the
real event object. They drifted on **which state**, which is a private, unshared step in the
counter.

`law_keys()` binds an enactment to the nearest state name in the **140 chars before** the verb.
The emitted text begins:

> `Newsom signed Senate Bill 813, authored by Sen. Jerry McNerney (D-Pleasanton), and Assembly Bill 1405…`

The verb `signed Senate Bill` is at offset 9. There is no state name before it — the digest
names the governor by surname and never the state. `before` is empty, the loop `continue`s, and
a first-in-the-nation AI law is not in the series.

**The 300-char cap was tested and ruled out.** The untruncated 886-char paragraph *does* contain
"California". Running the real event object with the full text substituted:

```
rule matches REAL event (300 chars):      True    law_keys -> []
rule matches FULL-text event (886 chars): True    law_keys -> []
```

California sits at offset 682 — *after* the verb, not before it. The cap is a real defect and it
is not this one. (Second night running that it was the attractive wrong answer.)

Measured across the trunk: **16 events match `ev-state-law-enacted`; 2 yield no law key
(12.5%)** — and the two fail for *different* reasons:

- **California, 2026-09-09** — no state name anywhere before the verb.
- **Washington, 2026-08-07** — "Washington" is present at offset 0, but the verb is at 184, so
  it falls outside `LOOKBACK = 140`. A genuine enactment ("four were adopted… and enacted this
  spring"), lost to window width.

**The obvious fix is one sentence from being wrong.** Adding a lookahead would find
"California" at 682 — correct here — but "Washington" follows at 750, referring to *Washington,
D.C.* and the federal government. A naive symmetric window records a Washington State AI law
that does not exist. Any fix needs a governor→state map and a D.C. guard, not a wider window.

Verified counterfactual: prefixing the state to the actor yields `['California|#813']` — one
row, not two. AB 1405 has no enactment verb of its own and would still be missed.

### 2. Correction — the three "misattributed" rows are correct; the preview field is the defect

Reading the emitted artifact, three of the eight counted laws looked wrong: **Nebraska #525**
carrying New York prose, **Idaho y2026** carrying the NCSL aggregate the module's own docstring
says it excludes, and **Montana y2026** carrying a survey of bills merely *under consideration*.

All three are right. Each row's stored `text` is a **180-char prefix**, and in each case the
enactment that justifies the row falls after the cut:

- `…; **Nebraska enacted LB 525** earlier in 2026, establishing…`
- `…; **Idaho enacted a law** requiring chatbots to refer suicidal users to crisis centres…`
- `…; **Montana enacted a Rig**[ht to Compute Act]`

The proximity binding is doing exactly what its docstring claims, and doing it well. What
misleads is that the counter's own display field truncates before the evidence in 3 of 8 rows,
so the artifact reads as a set of misattributions to anyone auditing it instead of the source.
Working Rule 8 caught this: the audit was wrong, not the app.

Read across the full baseline history rather than a two-night window, this is much larger than
the thirteen recorded on 2026-09-09.

- `review.pct` has tightened on **21 consecutive** baseline commits (2026-08-20 → tonight).
- Across all **42** pct-bearing commits it has **never increased**. The four non-tightenings

- `review.n` in `baselines.json` has taken two values ever — 223, 224 — and is frozen at **224**.
- The baseline's `events.n` has taken **one** value ever: **1825**, frozen since 2026-07-31.

So the gate ratchets a rate whose stored numerator and stored denominator are both artifacts
from July. `audit_all.py:294` makes the count unreachable once `pct` exists, and the module
docstring still advertises the contract the code no longer implements — "review — needs-review
count may not grow".

**The new part is the tolerance.** The failure condition is `pct > baseline + 0.5`. That 0.5pp
is a *rate*, so its absolute permissiveness grows with the corpus:

|---|---|---|---|
| baseline set 2026-07-31 | 1,825 | 9.1 items | — |
| tonight | 2,562 | **12.8 items** | **186.8** (against an actual 174) |

The floor tightens by hundredths of a point while the band above it widens by whole items. The
backlog could jump 174 → 186 tonight and the gate would pass.

**Tonight the count genuinely fell** — 175 → 174, the first real decrease in this window. It is
worth decomposing, because most of the reported improvement still is not work:

```
last night  175/2,544 = 6.8789%      tonight  174/2,562 = 6.7916%
```
