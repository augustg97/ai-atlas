### 5c. D's widener rose while D's page count did not move

D has had **126 direct pages for five mornings**. Its widening factor went 1.093 → 1.095 anyway,
and that width is what put D1/D3 motion on screen. The mechanism, from
`wiki_grounding.py:117-120`:

```python
ref = sorted(per_axis.values())[len(per_axis) // 2]   # the MEDIAN axis count
deficit = max(0.0, (ref - n) / ref)
widen[ax] = round(1.0 + 0.25 * min(1.0, deficit), 3)
```

The reference is the median axis, which is S. S gained two pages (201 → 203), so the median rose,
so D's deficit rose, so D's band widened. Reproduced exactly: prev (203−126)/203 → 1.093 becomes
(203−126)/203 → 1.095 at the new median.

**D's widener is a function of what the vault writes about the other six axes.** A morning in
which nobody writes anything about diffusion and labor, but somebody writes two pages about
compute, widens D. That is defensible as a relative-thinness measure and it is the design — but
it means "D's band got wider" never implies anything happened to D, and the panel's `width only`
label is now the only thing on screen carrying that. Yesterday's §5d asked which force moved D
