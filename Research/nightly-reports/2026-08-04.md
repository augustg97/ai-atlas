## 6. Two defects found this morning (both in the Atlas repo, neither a gate failure)

Neither is a wiki data defect, so **no queue task was filed** — the gate passed and the vault is
not implicated.

**(a) `marginals.json.history` records only the first chain run of a calendar day.**
`Research/timelines/forecast_emit.py:142` appends a history point only when
`history[-1]["date"] != today`. The chain ran twice on 2026-08-04 (r1 round 01:24, scheduled run
10:49), so the `2026-08-04` history point holds the **01:24** marginals (`C1 0.4061785687`) while
`today` holds the 10:49 values (`C1 0.4054791875`) — a 7.0e-4 gap on C1.

**Today's on-screen drift figures are correct.** `web/index.html:955` computes
`drift30 = activeMarginals() − history[max(0, len−31)]`: the near end is `today`, the stale point
is at the far end and is not yet in range. Verified against the rail for all seven axes —
T3 +0.6 · A3 +0.6 · C1 −1.5 · D2 +0.5 · S2 +0.5 · P3 −0.1 · E2 −3.9 — every one reproduces from
`today − history[0]`.

The error does not vanish, though; it **ages into position**. In roughly 30 days the 2026-08-04
point becomes the far end of that same comparison, and every axis's drift will then be measured
from the 01:24 run rather than the published 10:49 one — a fixed 7e-4 bias on C, smaller
elsewhere. Low severity today, wrong-by-construction later. It is a silent second-write discard
and the fix is one comparison.

**(b) The "what moved this morning" panel conflates application date with event date.**
The live panel reads **"19 applications on 2026-08-04 — all shown, newest first"**. All 19
`evidence_log` entries do carry `date: 2026-08-04`, but only **3** are applications of Aug-4
events; the other 16 are the r1 catch-up, applied today against events dated 2026-07-31 through
2026-08-03. The log's `date` is the **application** date — defensible as an update ledger — but
the panel's wording reads as "19 things happened on Aug 4". Against standing rule 12 (three date
kinds, never conflated) this wants an explicit `applied` vs `event` distinction in the entry and
on screen. Today is the only day the two will diverge this badly, which is exactly why it should
be fixed before it becomes invisible.
