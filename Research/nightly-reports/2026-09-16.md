## Findings

### The forecast's "today" is a constant set on July 31

The live page's forecast header reads **"Jul 2026 — today"** on a site stamped 20260916. It
is a literal. `web/index.html:1276` returns the string `"Jul 2026 — today"` whenever the cursor
is within 0.05 yr of `NOW_Y`, and `web/index.html:253` sets `const NOW_Y = 2026.58`, about
2026-07-31, the day v2 shipped (introduced in `d3dec54`, "T1-T4 shipped"). The T-axis curves in
`Research/timelines/worldlines.py` also start at a hard-coded knot `(2026.6, 2.6)`.

The weights behind the chart have taken evidence through 09-16, so the forecast isn't frozen
at July 31. The TODAY rule and its label are. Today's actual coordinate is ≈ 2026.71, **47 days
past** the drawn edge. CLAUDE.md defines today as "a hard right edge, advancing daily". If
`NOW_Y` is meant as the forecast's epoch, then the label is what's wrong and it should say so.
Either way, one of the two is misreporting.

Not fixed and no queue task. It's Atlas app code and the vault is not involved. It is the
same shape as the window-label family, a moving quantity stored as a literal. The fix should
derive `NOW_Y` and the label from the emit date (the staged files carry `date`), so the class
can't recur.
